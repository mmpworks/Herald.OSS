- **Branch:** `feat/serilog-compat`
- **Status:** Scope contract — pending user review, then Richard + Jared design rounds

## Intent

Lower the friction of moving off Serilog as close to zero as we can, and take Serilog's customers. Everything below is in service of that one goal. When a scope call is ambiguous, the tie-breaker is "which choice removes more friction for more real Serilog users."

## What we are building

A Serilog drop-in compatibility layer for Herald.OSS. A Serilog user replaces Serilog with Herald.OSS and their log-call code compiles and runs unchanged. We deliver it in two layers (the hybrid model):

- **Layer 1 — `MMP.Herald.Serilog.*`.** Serilog-shaped types in a Herald namespace. Source-compatible: a consumer changes one `using` per file (or one global using) and everything below it is identical. This layer can coexist with the real Serilog package, so a shop can migrate in stages and verify before cutover.
- **Layer 2 — `Serilog.*` shim.** Serilog's own namespaces and type shapes, mirrored onto Layer 1. A consumer swaps the package reference and changes nothing else. This is the literal zero-code-change path.

We mirror Serilog's *type shapes*. We cannot mirror Serilog's *assembly identity* — we do not have Serilog's strong-name key and will not spoof it. That single fact draws the hard edge of what can and cannot carry over (see Out of scope).

## Why this is achievable on the current engine

Herald.OSS on `main` (v0.10.3) already covers most of Serilog's call surface under different names:

| Serilog concept | Herald.OSS today | Work |
|---|---|---|
| Message templates `"User {Id}"` | Supported — named holes parsed | Match |
| `{@Obj}` destructure / `{$Obj}` stringify | `LogPropertyCaptureMode.Destructure/Stringify` (mode API) | Map inline syntax → capture mode |
| `ILogger.ForContext(...)` | `ILogger<T>.WithContext(dict)` | Same idea, alias |
| `LogContext.PushProperty(...)` | `BeginScope(dict)` / `ILogScope` | Same idea, alias |
| `LogEventLevel` (Verbose…Fatal) | `LogLevel` (Trace…Critical, no Fatal) | Level-name map |
| `LoggerConfiguration().WriteTo.X().Enrich.Y()` | `QuickLogBuilder.Create().WithXSink().WithEnrichers()` | Builder-shape map |
| MEL `ILoggerProvider` (`AddSerilog` underpinning) | `src/Addons/MelAdapter/HeraldLoggerProvider.cs` — already ships, full `Log<TState>`/`IsEnabled`/`BeginScope` | Expose under Serilog-shaped wiring |
| `Log.Information(...)` static facade | Does not exist — Herald is DI-first by design | New, **compat layer only** |

The MEL provider already shipping is the load-bearing fact for the ASP.NET story: `UseSerilog()` and `AddSerilog()` are thin wiring over a provider that already works.

## Win condition

A real Serilog app — code-configured **or** `appsettings.json`-configured, including the canonical ASP.NET Core wiring — swaps the package, builds clean on net9/net10, and produces equivalent structured output through Herald's engine, with **no measurable allocation or performance regression** on Herald's existing hot paths.

## Design-round outcomes & decisions (2026-05-29)

The Richard + Jared design rounds (with the-fool, Rosanne, Echo) are complete. Details: `design-round-richard.md`, `design-round-jared.md`, `seam-inventory.md`, `test-inventory.md`. Binding outcomes:

- **Honest claim (Steve decision).** The headline is *"Swap the package, rebuild, and your standard Serilog code runs on Herald — popular sinks map over; the third-party-sink ecosystem and the expression DSL are a documented boundary."* We do **not** market "1-to-1 / binary drop-in" — mirrored types give source compatibility on recompile, not binary identity (we won't spoof Serilog's strong-name key). The capability is unchanged; only the unspoofable wording goes.
- **Output-template grammar is v1 (Steve decision).** `{Timestamp:HH:mm}`, `{Level:u3}`, `{Message:lj}` etc. are built for v1 — it's a common config shape and degrades *silently* to wrong output if missing.
- **Two v1 additions the seam review surfaced (both abut the value model, both are fork-traps if deferred):**
  - **Config-name sink/enricher registry** — a public `LoggerSinkRegistry`/`LoggerEnricherRegistry` on the Apache-2.0 settings project so a shop's in-house sink wired *by name* in `appsettings.json` (`"Name": "MyCompanySink"`) resolves instead of forcing a parser fork. Unresolved names still fail loud + named.
  - **Raw `IDestructuringPolicy` bridge** — Herald's native policy returns a *string*; Serilog's returns a *tree*. The `ByTransforming(Func)` form maps; the raw-policy form must bridge to the value-model tree **or throw loudly at registration — never silently no-op** (a no-op'd redaction policy is a PII/security regression).
- **Value-model mirror (Jared sign-off): two structural guards required before merge.**
  - *Guard 1* — mirror construction is confined to the custom-extension dispatch site **by type, not comment**; an architecture test asserts no kernel/native-sink assembly references `Serilog.Events.LogEvent`. (Insulated structurally by the `readonly ref struct LogEventBuffer` — it cannot be a field of the heap mirror.)
  - *Guard 2* — the allocation benchmark gains a row proving the mirror contributes **0 B/op on the native-sink path** (referenced-and-loaded must equal absent).
- **Pre-existing latent bug to fix during the rename:** `KnownLogLevelKeys` (analyzer table) and `LogLevelKeys` (runtime table) are hand-authored and **already drift today** (stray `Fatal`). The rename touches both; a cross-table equivalence test must pin them equal (against the intended post-rename state).

## In scope (v1)

### 1. Core call surface (mandatory)

- `Serilog.ILogger` instance API: `Verbose/Debug/Information/Warning/Error/Fatal`, the generic typed overloads, `Write(LogEventLevel, …)`, the `ForContext(...)` overloads, `IsEnabled(level)`.
- Static `Log` facade: `Log.Logger`, `Log.Information(...)` and siblings, `Log.ForContext(...)`, `Log.CloseAndFlush()`. **Lives in the compat layer only.** Herald.OSS core stays DI-first and unmodified.
- Message templates including inline `{@destructure}` and `{$stringify}`, positional holes, and `{{`/`}}` escaping, mapped to Herald's capture modes and template parser.
- `LogEventLevel` ⇄ Herald `LogLevel` mapping (Verbose→Trace, Information→Info, Warning→Warn, Error→Error, Fatal→Critical, Debug→Debug).
- `LogContext.PushProperty(...)` ⇄ Herald scope.
- Serilog value model — scalar, sequence, structure, dictionary — captured with parity.
- `LoggerConfiguration` code config: `MinimumLevel.*`, `WriteTo.*`, `Enrich.*`, `.CreateLogger()`, mapped to `QuickLogBuilder` plus the sinks Herald already has (Console, File, HTTP/TCP/UDP, Elasticsearch, OTLP, Null).

### 2. `appsettings.json` configuration

`ReadFrom.Configuration(IConfiguration)` parity — `MinimumLevel`, `WriteTo`, `Enrich`, `Override` read from `appsettings.json`. A large share of production Serilog apps configure this way; without it they are not a drop-in.

Delivered as a **separate Apache-2.0 project** anyone can link independently. Preference order for Richard/Jared to resolve:
1. Reuse Serilog's existing `Serilog.Settings.Configuration` add-on if it can bind to the shim.
2. Otherwise build a `Herald.OSS.Serilog`-flavored equivalent against the same `appsettings.json` schema, pulling NuGet packages as needed.

The binding question is open because of the assembly-identity wall (see Open architecture questions).

### 3. ASP.NET Core integration

The canonical ASP.NET Core Serilog setup must drop in end to end:

- `Serilog.Extensions.Logging` equivalent — `AddSerilog()` wiring, over the already-shipping `HeraldLoggerProvider`.
- `Serilog.AspNetCore` — `builder.Host.UseSerilog(...)` host hook (builds the Herald logger, registers the provider) and `app.UseSerilogRequestLogging()` request-logging middleware (one summary line per HTTP request: method, path, status, elapsed).

The MEL wiring and `UseSerilog()` are cheap because the provider exists. The request-logging middleware is the one genuinely net-new component, and it is well bounded.

## Out of scope (v1)

- **Third-party / community sinks** — `Serilog.Sinks.Seq` and the rest. These are compiled against the real Serilog assembly identity and will not bind to the shim. "No custom sinks" rules out reimplementing them. This is a hard wall, not a deferral.
- We do **not** silently truncate the claim. The parity audit names every break.

Nothing else is deferred. v1 covers the call surface, `appsettings.json`, and the ASP.NET Core path — the three things that block the most real Serilog users.

## The parity audit (#4 deliverable) — reframed as a friction map

The audit is not a list of "what breaks" for its own sake. It is a friction map ranked by how many real Serilog customers each gap blocks, so we always attack the highest-population blocker first and so the marketing claim stays honest.

For each Serilog surface it records: does it carry over, does it map to a Herald equivalent, or is it a hard wall — and roughly how much of the installed base each case affects. The popular sinks (Console, File, Elasticsearch, OTLP, HTTP) map to Herald equivalents and are documented as such. Seq and the long tail are named as gaps.

Lands at `docs/serilog-compat/parity-audit.md`.

Where practical, a migration plan is produced for each gap. The plan is a series of steps for a SeriLog user to migrate the code gap to Herald. This SHALL be a documentation addition to the existing `docs/serilog-compat/README.md` (the "how to" guide) by direct text in the README.md OR a link to a companion document. (This will be in consult with Documentation Owners)

## Hard constraints

- **net9 + net10 only** for the compat layer. No net8 immediately. Herald.OSS core keeps its own target frameworks; the compat packages simply do not offer a net8 build.
- **CUPID + DRY — resolved as RENAME, not alias.** Several Herald concepts are the same idea as a Serilog concept under a different name (`WithContext`/`ForContext`, `BeginScope`/`PushProperty`, capture-mode/`{@}`/`{$}`, the builder verbs, the overlapping level names). **Decision: rename the Herald APIs to the Serilog names** rather than layering aliases. Herald.OSS has no users yet, so the breaking-change cost is mechanical and cheap now, and a single canonical name (the Serilog one) keeps future source simpler than a permanent two-name alias surface. See the dedicated section below.
- **No allocation or performance regression.** Serilog-shaped calls route into Herald's existing zero-allocation paths. Known-arity property arguments fold into the typed-args (1–16) / span path; `params object[]` is the fallback only when arity is unknown or exceeds the typed band. We benchmark the compat surface on net10 against Herald's own baseline **and** against real Serilog, and gate on no regression to Herald's hot paths.
- **AOT-clean.** Herald.OSS ships an AOT-clean default; the compat layer must not break it.

## Open architecture questions (Richard + Jared, design rounds)

1. **DRY mechanism — RESOLVED: rename.** Herald APIs are renamed to the Serilog names (breaking, but no users yet). Richard + Jared scope *which* renames and *in what order* — see the Rename refactor section.
2. **`Serilog.Settings.Configuration` binding.** Can the real add-on bind to the shim, or does the identity wall force a re-implementation in the Apache-2.0 project? This decides whether item 2 is "reference a package" or "build a parser."
3. **`params object[]` → typed-args lowering.** The exact mechanism that preserves zero-allocation — source generator, overload set, interpolated-string handler, or a combination.
4. **Layer-2 mechanism.** Type-forwarding versus mirrored types. The identity wall likely forces mirrored types rather than `[TypeForwardedTo]`.

## Rename refactor (resolved: rename Herald APIs to Serilog names)

With no Herald users yet, we take the breaking change now while it is mechanical and cheap, and converge on one canonical vocabulary — Serilog's — so the compat layer is a thin mapping and future source stays simple.

Two blast-radius tiers for Richard + Jared to sequence:

- **Low blast radius — inside Herald.OSS.** API method/type renames: `WithContext` → `ForContext`, `BeginScope`/`ILogScope` aligned to the `LogContext.PushProperty` model, builder verbs and possibly `QuickLogBuilder` → a `LoggerConfiguration`-shaped name, capture-mode entry points aligned to `{@}`/`{$}` semantics. Contained, source + XML-doc + README.
- **High blast radius — crosses repos.** Level renames for the overlapping six (`Info` → `Information`, `Warn` → `Warning`, `Critical` → `Fatal`, `Trace` → `Verbose`, plus `Debug`/`Error` already aligned). This ripples into the Dashboard SPA, the DemoApp seeds, and the level wire contracts (`Modules/Dashboard`, DemoApp, SSE level shape). Herald keeps its **extra** levels (Notice, Success, Security, Metric); only the six that overlap Serilog get renamed. Sequence this tier deliberately and update every wire/UI surface in lockstep.

Refactor crew (execution phase, after design + plan): Heather (docs), Echo (test updates + gap coverage), Glenn (mechanical rename application across call sites), Jared and Richard (architecture), and Max (build/packaging — `build.sh`, `Directory.Build.props`, the new project wiring). Design phase produces artifacts only; no source is renamed until the plan is approved.

## Testing (comprehensive)

- **Behavioral parity** — a given Serilog call produces a canonical-shape-equivalent Herald `LogEvent` (per the project's ingress↔output canonical-equivalence rule).
- **Real-Serilog corpus** — representative real Serilog snippets compile and run unchanged against the shim (call surface, code config, `appsettings.json`, ASP.NET Core wiring).
- **Tables** — level mapping; template parsing (`{@}`, `{$}`, positional, escaping); value model (scalar / sequence / structure / dictionary).
- **`appsettings.json`** — config round-trip.
- **ASP.NET Core** — `UseSerilog()` host wiring, `AddSerilog()` MEL wiring, request-logging middleware output shape.
- **Allocation / performance** — net10 benchmarks of the compat surface vs. Herald baseline and vs. real Serilog; gated on no regression to Herald hot paths.
- **AOT** — compat layer stays AOT-clean.
- **Every audited gap becomes a regression test** asserting the known limit (per the every-bug-becomes-a-regression-test discipline). A gap that is a whole class gets a functionality suite.
