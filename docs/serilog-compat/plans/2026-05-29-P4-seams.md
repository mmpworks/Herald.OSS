# P4 — Serilog-Compat Seams Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land the four v1 user-extension seams in `MMP.Herald.Serilog` so a Serilog shop's own sinks, enrichers, and destructuring policies keep working after the package swap — **S1** `WriteTo.Sink(ILogEventSink)`, **S2** `Enrich.With(ILogEventEnricher)` + the `ILogEventPropertyFactory` shim, **S5** the raw `IDestructuringPolicy` tree bridge, and **S9** `AuditTo` throw-on-failure vs `WriteTo` swallow. Every seam hands the user the **mirrored** Serilog `LogEvent` (P1's value model). The redaction path is security-critical: a no-op'd `IDestructuringPolicy` leaks PII, so S5 bridges to the tree projection or throws loud at registration — never a silent no-op.

**Architecture:** Each seam is a thin **adapter** from the Serilog-shaped contract onto the native Herald primitive. S1 wraps `ILogEventSink.Emit(LogEvent)` over the heap-sink path (`CustomSinkProvider` registration already exists). S2 wraps `ILogEventEnricher.Enrich(LogEvent, ILogEventPropertyFactory)` over native `ILogEnricher.Enrich(LogEventEnrichmentContext)`, with a `LogEventPropertyFactory` shim routing `CreateProperty(..., destructureObjects:true)` to `LogPropertyCaptureMode.Destructure` so `{@}` props reach the value-model tree instead of flattening. S5 bridges raw `IDestructuringPolicy` (Serilog returns a `LogEventPropertyValue` **tree**) onto the mirror's tree projection — Herald's native `IDestructuringPolicy.TryDestructure(object, out string?)` returns a **string**, so the two are not interchangeable and the adapter must NOT reuse the native string policy. S9 threads an `auditMode` bool from the `AuditTo` verb into the S1 sink adapter: default `false` swallows sink failures (matches `WriteTo`, reports via SelfLog), `true` re-throws (compliance contract). Per Richard's CUPID/DRY rule, every adapter type carries adapter logic only — any business behaviour belongs in the canonical Layer-1 impl, not a seam.

**Tech Stack:** C# / .NET (net9 + net10 target for the compat assemblies), xUnit, `bash build.sh`, BenchmarkDotNet (InProcess, net10) for the one alloc-isolation check. Plan-only here — no product source is written in this document.

**Native primitives this plan adapts (confirmed against the codebase):**

### Task 4: S5 — raw `IDestructuringPolicy` tree bridge (security-critical) — **redaction MUST fire**

Serilog's `IDestructuringPolicy.TryDestructure(value, factory, out LogEventPropertyValue tree)` returns a **tree**. Herald's native `IDestructuringPolicy.TryDestructure(object, out string?)` returns a **string** — they are NOT interchangeable. The adapter bridges the user's tree-returning policy onto the mirror's tree projection. **If the tree bridge cannot be built, throw loud at registration** — a silent no-op stops a password-stripping policy and leaks PII (a compliance incident / possible CVE). Never reuse the native string policy as a stand-in.
