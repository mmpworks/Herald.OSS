# UTF-8 format end-to-end — net10

End-to-end emit-to-UTF-8-bytes comparison. Each library configured
with its idiomatic "format to bytes then discard" sink so the bench
measures the format pipeline cost, not downstream I/O.

## Host

```
BenchmarkDotNet v0.14.0, Windows 11 (10.0.26200.8246)
12th Gen Intel Core i9-12900K, 1 CPU, 24 logical and 16 physical cores
.NET SDK 10.0.203
  [Host]     : .NET 10.0.7 (10.0.726.21808), X64 RyuJIT AVX2
```

## Setup

- **Herald** — kernel-eligible sink (`HeraldUtf8DiscardSink`
  implementing both `ILogger` and `IKernelSink`) wired via a custom
  sink provider that overrides the `null` kind. Format runs via
  `Utf8JsonFormatter.Format(in LogEventBuffer, IBufferWriter<byte>)`
  — no heap `LogEvent` materialization, no Dictionary, no property
  array. Writes UTF-8 directly to a reused `ArrayBufferWriter<byte>`.
- **ZLogger** — `AddZLoggerStream(Stream.Null)`. ZLogger writes
  UTF-8 directly to a stream; the null stream discards.
- **Serilog** — custom sink running `CompactJsonFormatter` to a
  `StringWriter` backed by a pooled `StringBuilder`. Serilog formats
  to UTF-16 strings; the rendered text is discarded.

## Results

| Method | Mean | Gen0 | Allocated |
|---|---:|---:|---:|
| Herald_Utf8Json_Discard | 442.3 ns | 0.0052 | 304 B |
| ZLogger_Utf8_StreamNull | 288.1 ns | — | 77 B |
| Serilog_CompactJson_Discard | 489.5 ns | 0.0162 | 968 B |

## Reading the table

- ZLogger leads on this workload by 1.5× over Herald and 1.7× over
  Serilog. ZLogger's UTF-8 pipeline integrates the interpolated
  string handler with direct byte writes; the format cost happens
  inside the handler call, not in a separate sink invocation.
- Herald's 304 B is the JSON output buffer plus per-event scratch
  the `Utf8JsonWriter` allocates internally.
- Serilog's 968 B reflects the UTF-16 string intermediate plus
  property-bag materialization.
