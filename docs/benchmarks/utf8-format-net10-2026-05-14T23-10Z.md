# UTF-8 format end-to-end — net10

End-to-end emit-to-UTF-8-bytes comparison. Each library configured
with its idiomatic "format to bytes then discard" sink so the bench
measures the format pipeline cost, not downstream I/O.

## Setup

- **Herald** — kernel-eligible sink (\`HeraldUtf8DiscardSink\`
  implementing both \`ILogger\` and \`IKernelSink\`) wired via a custom
  sink provider that overrides the \`null\` kind. Format runs via
  \`Utf8JsonFormatter.Format(in LogEventBuffer, IBufferWriter<byte>)\`,
  which switches on \`LogPropertyCompact.Kind\` to write primitives
  directly through \`Utf8JsonWriter\` (no boxing, no \`.ToString()\`).
- **ZLogger** — \`AddZLoggerStream(Stream.Null)\`. ZLogger writes
  UTF-8 directly to a stream; the null stream discards.
- **Serilog** — custom sink running \`CompactJsonFormatter\` to a
  \`StringWriter\` backed by a pooled \`StringBuilder\`. Serilog
  formats to UTF-16 strings; the rendered text is discarded.

## Results

| Method | Mean | Allocated |
|---|---:|---:|
| Herald_Utf8Json_Discard | 402.9 ns | 224 B |
| ZLogger_Utf8_StreamNull | 277.4 ns | 67 B |
| Serilog_CompactJson_Discard | 445.9 ns | 968 B |

## Reading the table

- ZLogger remains fastest by 1.45x over Herald and 1.61x over
  Serilog. ZLogger's UTF-8 pipeline integrates the interpolated
  string handler with direct byte writes; the format cost happens
  inside the handler call rather than in a separate sink invocation.
- Herald's 224 B is the JSON output buffer plus per-event scratch
  the \`Utf8JsonWriter\` allocates internally for property names and
  ISO-8601 timestamp formatting. Properties themselves contribute
  zero — they write directly from the typed slot.
- Serilog's 968 B reflects the UTF-16 string intermediate plus
  property-bag materialization.
