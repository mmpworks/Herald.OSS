# Typed-args accept path — net10

Herald's \`Info<T1..Tn>\` typed-args overloads at 4 and 16 properties,
across all-string and mixed-type shapes.

## Setup

The typed-args overloads (1..16 arity, generated by
\`TypedArgsOverloadGenerator\`) carry property values from the call
site through to a stack-allocated \`LogPropertyBuffer\` of matching
size. Each slot is a \`LogPropertyCompact\` with a typed-slot layout:
\`(string Name, LogPropertyKind Kind, long ScalarBits, object? RefValue)\`.
The generated overloads call \`LogPropertyCompact.From<T>(name, value)\`,
which JIT-specializes per \`T\` so primitive values flow into
\`ScalarBits\` and strings into \`RefValue\` without boxing.

## Results

| Method | Mean | Allocated |
|---|---:|---:|
| Herald_TypedArgs_FourProps_AllStrings | 30.18 ns | — |
| Herald_TypedArgs_FourProps_MixedTypes | 31.69 ns | — |
| Herald_TypedArgs_SixteenProps_AllStrings | 49.37 ns | — |
| Herald_TypedArgs_SixteenProps_MixedTypes | 43.22 ns | — |

## Reading the table

- Every shape is zero-allocation. Primitive types (\`int\`, \`bool\`,
  \`double\`) flow into \`ScalarBits\` via \`LogPropertyCompact.From<T>\`'s
  JIT-specialized path; strings flow into \`RefValue\` as references.
  No heap traffic per call.
- Mixed-types is meaningfully faster than all-strings at sixteen
  properties (43.22 ns vs 49.37 ns). The \`From<T>\` primitive arms
  compile to one or two instructions; the string arm goes through
  \`Unsafe.As<T, string?>\` plus the \`object?\` ref-store. At four
  properties the difference is within stddev.
- Per-property scaling is ~0.8-1.2 ns for primitives and
  ~1.2-1.5 ns for strings beyond the four-prop baseline. Sixteen
  properties costs roughly 12-19 ns over four properties.
