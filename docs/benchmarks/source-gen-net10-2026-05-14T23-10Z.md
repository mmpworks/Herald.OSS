# Source-gen head-to-head — net10 — 2026-05-14T23-10Z

Three libraries that ship a "declare it once, the generator emits the
body" path. Same template, same four arguments, same matching null
sink per library.

## Setup

Each library declares the same logging method via its source-gen
attribute:

```csharp
[HeraldLog(Level = "info", Category = "App",
    Message = "User {userId} purchased {sku} for {price} at {timestamp}")]
public static partial void Purchase(StructuredLogger logger,
    int userId, string sku, double price, string timestamp);

[ZLoggerMessage(LogLevel.Information,
    "User {userId} purchased {sku} for {price} at {timestamp}")]
public static partial void PurchaseZ(ILogger logger,
    int userId, string sku, double price, string timestamp);

[LoggerMessage(Level = LogLevel.Information,
    Message = "User {userId} purchased {sku} for {price} at {timestamp}")]
public static partial void PurchaseMel(ILogger logger,
    int userId, string sku, double price, string timestamp);
```

Sinks: Herald → `WithNullSink()`. ZLogger →
`AddZLoggerStream(Stream.Null)`. MEL → active-null provider
(formatter callback runs, output discarded).

## Results

| Method | Mean | Ratio | Gen0 | Allocated |
|---|---:|---:|---:|---:|
| Herald_HeraldLog | 34.39 ns | 1.00× | 0.0008 | 48 B |
| ZLogger_ZLoggerMessage | 172.54 ns | 5.03× | — | 5 B |
| Mel_LoggerMessage | 156.52 ns | 4.56× | 0.0041 | 232 B |

## Observations

- **Herald is 5× faster on latency.** 34 ns vs ZLogger's 172 ns
  and MEL's 156 ns. The `[HeraldLog]` generator emits a body that
  passes through Herald's full pipeline; the win comes from the
  kernel fast path that the pipeline ends at.
- **ZLogger wins on allocation.** 5 B per call vs Herald's 48 B
  and MEL's 232 B. ZLogger's source-gen path is genuinely close to
  zero — the 5 B is residual struct copy overhead BDN's counter
  picks up. Herald's 48 B is the `LogProperty[]` array the
  generator emits; future work could route the generator through
  the typed-args path to eliminate it.
- **MEL's source-gen still allocates 232 B.** That's the state
  struct + `KeyValuePair` array MEL's generator emits for the
  formatter callback. MEL's claim "source-gen eliminates boxing"
  is true for individual property boxing, but the per-call
  state-struct cost stays.

## Reading the chart

If your sole metric is per-call latency: Herald source-gen wins by
~5×. If your sole metric is per-call allocation: ZLogger wins by
~10×. If you want both reasonable in the same library: Herald is
the closest to the lower-left corner of the
latency-vs-allocation chart.

## Follow-up

The 48 B Herald allocation is the `new LogProperty[] { ... }` array
the `[HeraldLog]` generator emits. Routing the generator through
Herald's typed-args overload (`Info<T1, T2, T3, T4>(...)`) would
eliminate the array allocation entirely — the typed-args dispatcher
uses an `InlineArray<LogPropertyCompact, N>` on the stack. The
generator change is straightforward; pin the new numbers in a
future bench run.
