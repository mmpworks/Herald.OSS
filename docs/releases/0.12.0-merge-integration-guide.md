## What shipped

### Herald.OSS 0.11.0 → 0.12.0

Both versions are on NuGet. 0.11.0 and 0.12.0 are the same codebase; 0.12.0 is the version
the umbrella expects. If you are on 0.11.0, bump to 0.12.0 — no breaking changes.

**New packages (all Apache 2.0):**

| Package | Version | Purpose |
|---------|---------|---------|
| `Herald.OSS` | 0.12.0 | Core — now includes file-sink providers |
| `MMP.Herald.Serilog` | 0.12.0 | Layer-1 Serilog compat adapter (typed zero-alloc overloads) |
| `MMP.Herald.Serilog.AspNetCore` | 0.12.0 | `UseSerilog()` / `AddSerilog()` for ASP.NET Core |
| `Herald.OSS.Serilog.Settings` | 0.12.0 | `ReadFrom.Configuration(IConfiguration)` — appsettings.json |

### Key Herald.OSS changes

**Serilog drop-in compatibility (P0–P8)**
- `MMP.Herald.Serilog` — `SerilogLoggerAdapter` with typed zero-alloc overloads (arities 1–16).
  `{@}` destructure holes travel zero-alloc through the pipeline (Approach A: `CaptureMode` byte
  on `LogPropertyCompact`, struct stays 32 bytes).
- `MMP.Herald.Serilog.AspNetCore` — `UseSerilog()` / `AddSerilog()` / request logging middleware.
- `Herald.OSS.Serilog.Settings` — `ReadFrom.Configuration(IConfiguration)` parses MinimumLevel,
  WriteTo, Enrich, Using from appsettings.json.
- Layer-2 mirror (`Serilog.*` namespace) ships as a **local assembly swap only** — not a NuGet
  package. It replaces `Serilog.dll` in-process for zero-code-change migration.

**Kernel fixes**
- `LogPropertyCompact` gains a `CaptureMode` byte axis — struct stays 32 bytes.
- `implicit operator LogProperty(LogPropertyCompact)` now preserves `CaptureMode` (was lossy).
- `FastPathAsyncSink` drop counter fixed — `BoundedChannelFullMode.DropWrite` caused `TryWrite`
  to return `true` on overflow, making `DroppedCount` permanently 0. Fixed to `Wait` mode +
  non-blocking `TryWrite`.

**File-sink providers bundled into Herald.OSS core**
- `TextFileSinkProvider`, `JsonFileSinkProvider`, `FileSinkRegistration` and their internals now
  live in `Herald.OSS` (`src/Sinks/File/`). `WriteTo.File` works on a bare
  `PackageReference Herald.OSS` — **no separate Herald.Sinks.File package required**.
- Regression test `FileSinkDefaultProviderRegressionTests` pins this contract.

**Level rename (0.12.0)**
- `KnownLogLevels.Info` → `KnownLogLevels.Information`
- `KnownLogLevels.Warn` → `KnownLogLevels.Warning`
- `Critical` level removed — `Fatal` is the surviving top-level key.
- Any code comparing against the old short keys (`"info"`, `"warn"`, `"crit"`) must be updated.

### Herald.Sinks (fleet-wide batching — commit `e7f761c`)

**Problem fixed:** every network sink did one blocking synchronous HTTP POST per event.
At 250 kHz this stalled the producer. `IBatchedLogSink.LogBatch` was never called.

**Solution:** `Herald.Sinks.Batching` package — a shared `BatchingLogSinkDecorator` that every
network sink wraps with one line in `CreateSink`. Producers never block; a bounded
`Channel<LogEvent>` drain accumulates by size or time and calls `LogBatch` in the background.

**`Herald.Sinks.Batching` package:**
- `BatchingLogSinkDecorator` — bounded `Channel<LogEvent>` (8192 default), single drain task,
  flush at 256 events or 1 s, `LogBatch` on drain thread, per-event failure reporting,
  drain-on-dispose with 5 s timeout.
- `BatchingOptions` — reads `batch_size` / `flush_interval_ms` / `queue_capacity` from sink
  config (snake_case keys, matching mmpform DSL convention).
- `BatchingNetworkSinkBase : HeraldSinkBase, IBatchedLogSink` — default `LogBatch` loop for
  sinks without a native batch API. Override for efficient native-batch implementations.

**Scope:** 79 network sinks wired (61 already had `IBatchedLogSink`; 18 newly added via
`BatchingNetworkSinkBase`; `ProtobufFileLogSink` provider-only wire).

**`Herald.Sinks.File` slimmed** — providers are now in Herald.OSS core. The package is a
metapackage shell; `Herald.Sinks.File.Tests` retired from the solution (tests moved to Herald.OSS).

**Level-key mappers updated** — 21 production mappers updated to long keys
(`information`/`warning`/`fatal`/`verbose`) to match Herald.OSS 0.12.0.

## What your team needs to do

### Any project referencing Herald.OSS

1. **Bump `Herald.OSS` from any prior version to `0.12.0`**.
2. **Fix level-key references** — replace `KnownLogLevels.Info` → `.Information`,
   `KnownLogLevels.Warn` → `.Warning`, `KnownLogLevels.Critical` → `.Fatal`.
   Grep: `KnownLogLevels\.Info\b`, `KnownLogLevels\.Warn\b`, `KnownLogLevel.*Critical`.
3. **Fix level string literals** — any code comparing against `"info"` / `"warn"` / `"crit"` /
   `"trace"` (Herald's internal key strings) must use `"information"` / `"warning"` / `"fatal"` /
   `"verbose"`.
4. **File sink** — if your project referenced `Herald.Sinks.File` to get `TextFileSinkProvider`
   or `JsonFileSinkProvider`, those types now live in `Herald.OSS`. Remove the `Herald.Sinks.File`
   package reference; the types resolve from `Herald.OSS` automatically.
5. **`implicit operator LogProperty(LogPropertyCompact)`** — if any code used this operator on a
   `{@}` or `{$}` compact slot, it previously lost the `CaptureMode`. It now preserves it. Review
   any downstream rendering that reads `CaptureModeOrDefault`.

### Any project using Herald.Sinks

1. **Bump `Herald.Sinks.*` to the latest tag** (commit `e7f761c` on `main`).
2. **Batching is on by default.** Every network sink now batches at 256 events / 1 s flush.
   To disable for a specific sink, set `batch_size: 1` in the sink's config.
3. **Property-bag keys changed** — if code reads batching config from a `LoggingRuntimeSinkDefinition`
   directly, the keys are now snake_case: `batch_size` / `flush_interval_ms` / `queue_capacity`
   (were camelCase `batchSize` etc. briefly in WIP).
4. **Level-key test assertions** — any test asserting on Herald level output strings must use
   `"information"` / `"warning"` / `"fatal"` / `"verbose"`.

### Serilog migration (optional)

If your project currently uses real Serilog:

```csharp
// Layer 1 — source-compatible (coexists with real Serilog, typed zero-alloc path)
dotnet add package MMP.Herald.Serilog
dotnet add package Herald.OSS.Serilog.Settings   // for appsettings.json

// Layer 2 — literal zero-code-change (replaces Serilog.dll, cannot coexist)
// Ship as local assembly swap — see docs/serilog-compat/migration-runbook.md
```

Honest claim: "Swap the package, rebuild, and your standard Serilog code runs on Herald."
Binary-compat with real Serilog add-ons is NOT supported (assembly identity wall).
